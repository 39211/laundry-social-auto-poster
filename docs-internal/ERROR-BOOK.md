# 私享家產線踩坑簿(每個都真的發生過)

> 規則:每踩一個新坑,**當天**加一條。格式固定:`症狀 → 真因 → 修法 → 怎麼再驗一次`。
> 這份是給接手者看的。**動手前先掃一遍與你任務相關的段落**,不要用別人的血再流一次。

---

## A. 內容正確性(最貴的坑,會直接發錯東西給客人)

### A1|改了主題卻沒改圖片提示詞 → 文不配圖上線
- **症狀**:貼文寫「書包背帶」,圖是帆布鞋。
- **真因**:我改了 `topic` 和 captions,忘了 `image_prompt` 與 4 張輪播的 prompt 是獨立欄位。
- **修法**:改主題必須**同時**改 `image_prompt` + 每個 `carousel_items[].image_prompt`,刪舊圖、刪 day-lock、重生圖、**親眼看圖**、重鎖。
- **再驗**:生成後開圖看,不是看檔案存在。已加「文不配圖閘」(manifest fail-closed),但閘擋的是缺圖,**擋不了畫錯東西**——只有人眼能擋。

### A2|已存產出陷阱:改了生成器,行事曆還是舊內容
- **症狀**:改完 prompt 規則,產出完全沒變。
- **真因**:當日行事曆 JSON 已經存在,裡面帶著**上一版產生的成品文字**,生成器不會覆蓋已存欄位。
- **修法**:改生成器後,要嘛刪當日行事曆重生,要嘛直接改行事曆裡的欄位。踩過三次。
- **再驗**:改完後 grep 行事曆確認新規則的特徵字串真的出現。

### A3|舊 day-lock 把新內容打回去
- **症狀**:明明改成書包,隔天變回床組。
- **真因**:day-lock 是「當日內容正本」,heal 機制會拿鎖去覆蓋行事曆。鎖是舊主題,就把新的救回舊的。
- **修法**:**刻意重做流程** = 先刪 `data/day-locks/<date>.json` → 改內容 → 驗圖 → `npm run day-lock -- --date <date>` 重鎖。
- **再驗**:重鎖後比對 `day-locks/<date>.json` 的 topic 與行事曆 topic 一致。

## B. 驗證方法本身出錯(最陰險:讓你以為壞了,或以為好了)

### B1|cp950 假陰性:中文比對「不報錯、直接 0 命中」
- **症狀**:驗證 YouTube 描述,回報「參考價/至善國中/儲值全都沒有」——實際上線上全都有。
- **真因**:內容經過 shell 管線/檔案落地時被 cp950 毀了,我拿**損壞的資料**去比對,Python 又用 `errors='replace'` 吞掉,毫無錯誤訊息。
- **修法**:中文比對**抓取與比對必須在同一個 Python 程序內完成**,不經過 shell 管線、不落地中間檔。
- **再驗**:同一份內容故意打錯一個字,比對必須變 False——比對器要能分辨真假,不然它只是在說「找不到」。

### B2|退出碼與自述不可信
- **症狀**:腳本 exit 0,但實際沒發文;或 exit 非 0,但其實發成功了。
- **真因**:發布鏈有多段,退出碼只反映最後一段。
- **修法**:發布真相**只看 `data/posted-log/<date>.json`**;YT 看 `data/youtube-log/`;結算看 `output/day-reports/`。
- **再驗**:任何「已完成」都要指出是哪個檔案的哪一筆記錄。

### B3|閘門自己壞掉時等於全放行(Grok 紅隊找到,最重的一條)
- **症狀**:PreToolUse 閘門拋例外 → exit 1;但攔截條件是 exit 2 → **全部放行**。
- **真因**:fail-open 預設。
- **修法**:閘門一律 fail-closed;例外路徑也要回攔截碼。
- **再驗**:故意讓閘門拋例外,確認它擋下來而不是放行。

### B4|檢查器搜的是「我在對話裡發明的名字」,不是程式裡真實存在的字
- **症狀**:驗證「船長方法有沒有真的進生產」,回報三幕相機節拍「文件無、生產無」——實際上它完整存在於 `scripts/produce-next-reel.ps1:508-519`。
- **真因**:我搜 `push-to-defect`／`hold-on-contact` 這類**簡稱**,那是我在對話裡為了溝通方便造的詞,程式裡寫的是完整英文指令(`a slow push-in that ends framed on the worn area`)。**簡稱只活在對話裡。**
- **修法**:查「某個概念有沒有被實作」時,先打開檔案看它**實際怎麼命名**,再用那個字串搜;或搜行為特徵(函式名、switch 分支)而不是概念名。
- **再驗**:對一個**已知存在**的功能跑同一套檢查,回 False 就是檢查器壞了,不是功能不見了。
- **與 B1 同源**:兩者都是「驗證方法本身出錯,而且錯得很有說服力」。

### A4|同一支影片配同一則文案,隔天再發一次(2026-08-07~11 發生四次)
- **症狀**:IG 上 8/10 12:01 與 8/11 20:31 是同一支皮鞋影片、同一則文案;窗簾、後背包同樣各兩次。觸及從 169 掉到 26-87。
- **真因**:`generateDailyContent.ts` 保留「已排定的 reel slot」時保留**整個 slot 物件**,文案跟著影片從前一天中午被帶到隔天晚上。程式碼註解只想保住影片檔,實際連文字一起保住了。
- **修法**:只保留媒體欄位(`media_type`/`local_video_path`/`topic`),文案永遠屬於當天;另加發布端查重閘(近 7 天有逐字相同且真的發布過就拒發)。
- **再驗**:突變實測——拿掉查重閘,`test/publishGuards.test.ts` 必須變紅(已驗證)。

### B5|dry-run 寫出空的指紋檔,反而讓指紋閘失效
- **症狀**:`data/approved-log/2026-08-12.fingerprints.json` 內容是 `{}`,而當天核准檔根本不存在。
- **真因**:dry-run 跳過核准紀錄卻仍寫指紋檔;而發布端寫 `if (expected && expected !== actual)`,**沒有條目就短路放行**。檔案存在 = 宣稱已指紋化,但實際不檢查任何東西。
- **修法**:指紋寫入移進 `if (!options.dryRun)`;發布端把「有指紋檔但缺這個 slot」改成**拒發**。
- **再驗**:突變實測——把缺項判斷改成永不成立,測試必須變紅(已驗證)。
- **通則**:**空的保護檔比沒有保護檔更危險**,因為它讓檢查看起來存在。

### B6|測試全綠不代表保護有效——刪掉保護仍然全綠
- **症狀**:199 個測試全綠,但跨家族審核把七天重複閘、文不配圖閘、指紋比對、單飛鎖、NonRetryableError、healDay 逐一刪掉重跑,**結果與基準完全相同**。
- **真因**:那些機制**根本沒有對應測試**(grep `fingerprint`/`dayLock`/`NonRetryableError` 於 test/ 零命中)。
- **修法**:寫測試時同時做突變實測——拿掉被保護的那一行,測試必須變紅;不會變紅的測試要刪掉,不要留著當防禦縱深。
- **實證**:我今晚新寫三條,其中一條(dry-run 不留痕)拿掉保護仍全綠,因為 autoApprove 在寫指紋前就先拋錯 → **已刪除該條**,不留假綠。

## C. 這台機器 / PowerShell 5.1

### C1|bash 的時鐘會偏移數小時
- **症狀**:以為是凌晨 3 點,實際上午 9:41,判斷全錯。
- **真因**:`TZ=Asia/Taipei` 在這台的 bash 會退回 GMT。
- **修法**:**時間一律以 PowerShell `Get-Date` 為準**。

### C2|heredoc 寫 Python 時反斜線被吃掉
- **症狀**:路徑 `data\run-locks` 變成 `data<CR>un-locks`。
- **真因**:`\r` 被當跳脫字元。
- **修法**:路徑用正斜線,或 `chr(92)` 明確組字;讀檔用 `newline=''`。

### C3|`ConvertFrom-Json` 管線形式在 5.1 會炸
- **修法**:用引數形式 `ConvertFrom-Json -InputObject $text`,不要 `$text | ConvertFrom-Json`。

### C4|Write/Edit 寫出的 `.ps1` 沒有 BOM,含中文直接語法錯誤
- **修法**:寫完補 UTF-8 BOM。

## D. 排程與併發

### D1|死觸發:排程存在但 NextRunTime 空白 = 永遠不會跑
- **症狀**:任務在清單裡,卻從來沒執行。
- **修法**:watchdog 已加偵測(NextRunTime 空 → 重新註冊)。人工檢查:`Get-ScheduledTaskInfo` 看每一條的 NextRunTime。

### D2|一次性觸發加上去會蓋掉每日觸發
- **症狀**:補一個 `-Once` 觸發後,每日排程消失。
- **真因**:`Set-ScheduledTask -Trigger` 是**取代**不是追加。
- **修法**:`-Trigger (@($t.Triggers) + $once)` 保留原有的。
- **再驗**:設定後列出 Triggers,確認 Daily 和 Once 兩條都在。

### D3|同一支腳本被兩個排程同時叫起 → 內容互相踩踏
- **修法**:單飛鎖(publish 用 date+slot,生產腳本用 run-lock,30 分鐘視為過期可回收),排程設 MultipleInstances=IgnoreNew。

## E. 對外 API

### E1|`media_publish` 之後絕不可重試
- **真因**:那一刻貼文可能已經建立,重試 = 重複發布。
- **修法**:`NonRetryableError`,網路中斷或 5xx 都不重試,改去查 posted-log 與後台實際狀態。

### E2|限動轉發 404:行事曆帶著影片網址,但影片其實沒產
- **修法**:`verifyPublicAssetUrl` 先驗,失敗就 fallback 用圖。

### E3|Meta token 貼成 User Token 會讓整條鏈失效
- **修法**:必須是 **Page Token**,用 repair-meta-token 修。

## F. 專案管理 / 我自己犯的

### F1|海報做成價目表(v1)、做成整齊卡片(v2)—— 兩次都被退
- **真因**:我把海報當「文件排版」,做了三個區塊平均分配。真海報是**一個絕對主角 + 極端比例對比**,3 公尺外要能讀。
- **修法**:先讀規則(單一焦點/視覺階級/前後對比版式)→ 出規格 → 找設計總監複審 → 才渲染。v3 = 滿版出血 62% + 標題咬圖 + 金色只給兩處。
- **教訓**:視覺產出**不要自己一版定稿**,先找複審。

### F2|一次改多個變數,數據就廢了
- **修法**:每批只動一個變數(節奏 or 鉤子 or 長度,不可同時)。人設上線也要避開 A/B 期間。

### F3|素材排程排到期末就斷,生產線找不到東西做
- **症狀**:A/B 計畫只排到 8/14,8/15 之後生產線空轉。
- **修法**:排程表要**永遠比生產視窗多兩週**;生產視窗 4 天(原本 3 天太緊,失敗一次就開天窗)。
- **再驗**:每週檢查 `data/ab-test-plan.json` 最後日期 ≥ 今天 +14。

### F4|不獨立驗證交回來的東西,等於沒驗
- **實證**:我自測 15/15 全綠的 hook,Grok 判 EXPLOITABLE(16 條攻擊)、Opus 判 18 個 DEFECT。
- **修法**:自測全綠只是最低門檻。會影響放行的東西(閘門/計分器/驗證器)一律再送深審+跨家族紅隊。

### F5|實驗被綁在「有沒有新東西要做」上,結果實驗跑在零素材上
- **症狀**:A/B/C 中段治療排在 8/12-14,但生產腳本只在「有待產概念」時才進入生產體。所有概念都已產完 → 治療組裝是死碼 → 三天後會得到「中段治療無效」。
- **真因**:治療是**重剪已有素材**,不需要新概念,卻寫在「找新工作」的分支裡。
- **修法**:治療日改為挑「當天計畫要播的概念」重剪;覆蓋標準檔名前先保留 `-untreated` 版(同概念之後還會再播)。
- **再驗**:實測選取回傳當天要播的概念與 variant,不是 null。
- **通則**:**實驗的觸發條件不可以跟生產的觸發條件共用**。得到「無效」時要先問「它到底有沒有被執行過」。

### F6|用絕對座標排版,元素會互相疊上去而且不會報錯
- **症狀**:海報 v4 第一版的 QR 白框直接壓在優惠塊文字上。
- **真因**:各元素用 `H - 固定值` 各自定位,沒有人負責檢查總高度。
- **修法**:改成由上到下累加的 mm 預算,存檔前 `assert` 總和與底部界線。
- **再驗**:故意把某段高度加大,assert 必須擋下來。

### F7|只算區塊高度、不算文字實際佔高,文字會壓在下一個元素上而不報錯
- **症狀**:海報 v5 第一版「儲值 1000 送 100」壓在「運動鞋 $250 起」上面。v4 也犯過同型(QR 壓優惠塊)。
- **真因**:我用「這一塊我給它 30mm」來排版,但 20.8mm 的中文字實際佔高約 26.6mm(字級 ×1.28),加上內距就溢出。**PIL 畫字不會抱怨越界。**
- **修法**:畫字的函式回傳「文字底部座標」,後續元素一律以它為起點;每個容器存檔前斷言內文底部 ≤ 容器底部。
- **再驗**:故意把字級調大 20%,斷言必須擋下來(v5 實測擋下了兩次)。

### F8|用眼睛決定字級,就會做出走過去才看得到的海報
- **症狀**:v3/v4 的副標 7.5mm、優惠 10mm —— 分別要走到 0.9m 與 1.2m 才讀得到,而海報貼在門口是給 2-3m 外的人看的。
- **真因**:沒有把「這個字要在幾公尺外被讀到」變成參數,只憑畫面比例挑大小。
- **修法**:字高 = 閱讀距離(m) × 8.33(業界規則:1 英寸/10 英尺);先宣告每個元素的目標距離,字級由公式產生。主圖高度是可以退讓的,字高不行。
- **再驗**:拿同一把尺回頭量舊版,失敗項要能被指認出來(已量,v3/v4 各三項不合格)。
