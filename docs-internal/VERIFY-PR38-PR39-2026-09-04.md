### F1. #39 catch **不是**「只吃 Refusing image fallback」— reel / slot 3 會吞掉缺圖（獨立重現）

PR #39 commit / body 寫：「Catch the refusal only… anything else still propagates。」

實際程式（`src/scheduleAhead.ts:189-198`）：

```ts
} catch (error) {
  if (!slotRequiresPublishedVideo(slot)) throw error;
  // 沒有 message.startsWith('Refusing image fallback')
  results.push({ action: "skipped", reason: `reel video not publishable yet (${reason}); …` });
  continue;
}
```

`resolveSlotPublishMedia`（`src/postCurrentSlot.ts:129`）**先** `await assertLocalImagesExist`，**之後**才進影片 try/catch。缺圖丟的是：

`Image is missing for slot N: …`（`src/postCurrentSlot.ts:75-77`）

**沒有** `Refusing image fallback` 前綴。影片缺失才會被內層 wrap（`src/postCurrentSlot.ts:152-154`）。

本機 failing-test-first（已還原）：

- 測試名：`VERIFY: missing image on a reel slot still aborts the day (does not skip as deferred video)`
- 操作：seed slot 1 image + slot 3 reel，`unlink` `docs/assets/2026-09-21/slot-03.png`，期望 `rejects.toThrow(/Image is missing for slot 3/)`
- **現況：promise resolved，不 throw**
- 結果：
  - slot 1：`scheduled`（當天其餘槽繼續）
  - slot 3：`skipped`
  - reason：`reel video not publishable yet (Image is missing for slot 3: docs/assets/2026-09-21/slot-03.png. Run the Codex imagegen automation first.); live path owns it`

這把**出版阻擋條件（缺圖）**誤標成 **Reel 影片未就緒**。與 daily-automation 契約「Image fallback is not permission to bypass missing images」衝突。
