## Algorithm (design sections 4.2 and 5 are authoritative; summarized)
- Replay ledger: dedupe by event_id; sort by ts then event_id; record coverage gaps (corrupt lines, truncated tail) and `inquiries_from/through`.
- Inquiry = first qualifying `message_observed` per (shop_id, oa_scope, user_key, Taipei calendar day). `first_intent` from that first message. Source = first valid `source_code` of the day (`source_effective_at` = that message's ts); later different codes -> conflict reason, no override; `source_corrected` events (with `source_code`, `inquiry_id`) override explicitly.
- Identity timeline from `binding_observed/confirmed/revoked`: `confirmed` only counts for the main numbers; `observed`-only -> `candidate_only`. Composite/ambiguous cids -> `identity_ambiguous` -> unknown.
- POS pieces: dedupe by piece_id; parse `received_at`; date-only values are a whole-day interval: count only if the whole interval is inside the window AND after source/binding effective time; if it straddles a boundary -> `date_boundary_unknown`.
- I7: window `[t_i, t_i+168h)`. B7: `t_b = t_i` if a confirmed binding was in effect at t_i, else first confirmed binding after t_i within `[t_i, t_i+168h)` (later -> `late_binding`); window `[t_b, t_b+168h)`.
- Allocation: each piece is allocated at most once per policy, to the nearest preceding eligible inquiry of the same cid_key (tie -> inquiry_id order). Multiple users sharing one cid without a single confirmed mapping -> `shared_cid_conflict`.
- Status per inquiry (priority): unknown (identity/source/alloc undecidable) > received > unknown (coverage/POS gap affecting it) > pending (window not matured by as_of or POS data not through window end) > matured_no_receipt.
- `status` of the file: `complete` only if coverage has no gaps and POS data covers through the latest window end; else `lower_bound`.
- Cohort week: ISO week of t_i in Asia/Taipei (Mon 00:00). The exporter takes `--week 2026-W44` (default: last completed week) and `--as-of` (default now).
