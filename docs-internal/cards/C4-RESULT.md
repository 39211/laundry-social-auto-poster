# C4 結果：回購分群＋回測（前 6 個月 → 後 3 個月命中率）

## 執行方式

本次使用的指令（在 repo 根目錄執行）：

    python -B -X utf8 scripts\crm\repurchase_backtest.py --repo-root C:\Users\cyc39\laundry-repo --private-dir C:\Users\cyc39\laundry-repo\data\crm

- 只看摘要、不寫任何檔案：在指令後加 `--dry-run`
- 指定截止日：`--as-of 2026-03-31`（預設＝資料中最新的收件日）
- 離線／測試：`--source json --json path\to\data.json`
- 單元測試（離線、只用合成資料，不連 MDB）：

      python -B -X utf8 -m unittest discover -s scripts/crm -p "test_*.py"

## 產出

| 產出 | 位置 | 內容 |
|---|---|---|
| 報告 | `reports/crm/crm-backtest-<YYYY-MM-DD>.md` | 只有彙總數字（繁體中文），第一行為結論 |
| 聯絡候選名單 | `<private-dir>/crm-contact-candidates-<YYYY-MM-DD>.csv` | 含編號、姓名、電話與採用的規則（`rule` 欄）；第一行註明「do not send without owner approval」；`data/crm/` 不進版本控制 |

`--private-dir` 若位於 repo 內，必須在 `<repo-root>/data` 底下（`data/*` 已設為 git 忽略），其他 repo 內的位置一律報錯（結束碼 1）；repo 以外的位置可以使用。

## 定義與指標

- **收件單號（Did）**：一張收件單，可包含多件衣物；同一張單的所有列都是同一位客人、同一收件日。
- **單件編號（Dno）**：每一件衣物的編號。
- **去重方式**：以「收件單號＋單件編號」（去除前後空白）為鍵。同一件同時存在於 Det（歷史）與 Deh（現行）時以 Deh 為準；同一表內完全相同的重複列只算一列；單件編號空白的列一律保留。
- **來店**：同一客人、同一收件日算一次。消費金額＝各件 Tpay 加總（Tpay 為 0／空白時用 Price×Qty）。
- **分層**：新客＝1 次、回頭客＝2–4 次、常客＝≥5 次；活躍度：近 6 個月（183 天內）／6–12 個月／12 個月以上未來。
- **個人週期**：≥3 次＝相鄰來店間隔中位數；2 次＝該間隔；上限 365 天。單次客用「來店 ≥2 次客人的週期中位數」，主要品項為寢具者用寢具客的中位數。
- **到期分數**＝距上次來店天數 ÷ 週期。已到期＝1 ≤ 分數 < 3 且距上次 ≤ 365 天；14 天內到期＝目前 < 1、14 天後 ≥ 1。
- **回測**：2024-04-30 起每月月底為截止日 T，只取 T+90 天已有完整資料的月份。母體＝T 前 6 個月有來店的客人；結果＝(T, T+90 天] 是否再來。
  - 命中率＝名單中有回店的人數 ÷ 名單人數
  - 合併命中率＝各月命中總和 ÷ 各月名單人數總和
  - 召回率＝名單命中人數 ÷ 母體中所有回店人數
  - 提升＝命中率 ÷ 當月基準回店率（>1 代表比「全部都聯絡」更準）
  - 名單人數為 0 的月份不計入該規則的平均命中率與平均提升

## 比較的名單規則（皆事先訂定，在同一母體上評估）

| 規則 | 代號 | 定義 |
|---|---|---|
| 基準 | `baseline` | 近 6 個月有來店的全部客人 |
| 到期規則 | `due` | 1 ≤ 到期分數 < 3，且距上次 ≤ 365 天 |
| 分數前 K 名 | `topk` | 依到期分數排序，取與到期名單同樣人數 |
| 最近一次來店在 30–90 天前 | `recent_30_90` | 距上次來店 30～90 天（含） |
| 多次且逾期 | `multi_lapsing` | 來店 ≥3 次，且距上次天數介於週期的 0.8～2.0 倍（含；週期上限 365 天、距上次 ≤ 365 天） |

報告與螢幕輸出用同一張表列出每個規則的平均命中率、合併命中率、平均召回率、平均提升與平均名單人數。

## 結論與聯絡名單規則的選擇方式

- 結論句（報告第一行、螢幕第一行）會直接寫出「依平均提升，回測最好的規則」。
- 到期規則的平均提升低於 1 時，結論句會寫明：到期規則並沒有比直接聯絡「近 6 個月有來店的全部客人」更準。
- 聯絡名單採用平均提升最高的規則（基準不列入選擇）；同分時用到期規則。
- 若沒有任何規則的平均提升高於 1.0，名單仍用最佳規則產出，但報告與 CSV 第一行會加註「回測沒有任何規則比全體基準準，名單僅供參考」。
- 使用到期規則時，名單＝已到期＋14 天內到期的客人；使用其他規則時，名單＝目前近 6 個月有來店、且符合該規則的客人（與回測相同）。
- 本次實際數字：（待實際執行後由負責人填入）

## 限制

- **Det／Deh 保留**：衣物同時存在於 Det 與 Deh 時以「收件單號＋單件編號」去重、以 Deh 為準。若店內系統曾清除舊的歷史資料，早期來店次數會偏低。
- **公司／散客帳號**：Cid 空白、全為 0，或「來店次數前 0.5% 且每年 >150 次」者會被排除，只回報個數。判定使用全期資料，可能有遺漏或誤判。
- **民國日期**：`YYY.MM.DD` 加 1911 換算；空白或格式錯誤的日期略過並計數。
- **左截斷**：資料自 2022-03-17 起，早期的「新客」可能其實是舊客。
- **相關不等於因果**：命中率是「依規則挑出的人本來就會回來」的比例，不是聯絡後的效果。實際效果需另做對照測試。
- **寢具判定**：依品項分類名稱是否含「寢具／棉被／被／床／毯／枕」等關鍵字（可用 `--bedding-keywords` 調整）。

## 實跑結果（2026-10-30，總指揮在 ai 機以唯讀方式跑真 MDB）

- 資料：2022-03-17～2026-10-30，分析客數 2,229 位，去重後 37,989 件。合併的重複只有 20 列。
- r1 誤用 Did（收件單號）去重，只剩 12,891 件，金額和品項比例都被低算。r2 改用 Did＋Dno 後才正確。
- 回測共 28 個月（2024-04～2026-07 月底），以 90 天內是否回店計算。
  - 基準（近 6 個月有來的全部客人）：命中 35.0%。
  - 到期規則：30.7%，提升 0.88。**比基準差。**
  - 前 K 名：25.6%，提升 0.73。
  - 30–90 天前來過：32.6%，提升 0.93。
  - **來店 ≥3 次且距上次為週期的 0.8–2.0 倍：55.4%，提升 1.59，28 個月中每月都 >1。**
- 這兩條替代規則是在看到到期規則不如基準之後才加入的，但門檻在第一次跑之前就寫定，沒有依結果調整。
- 這是相關，不是因果。命中率高的一部分原因可能只是「來過 ≥3 次的人本來就常回來」。聯絡之後實際能多回來幾位，要做對照測試（C5）才知道。
- 新客 90 天回店率：31.5%（620/1,967）。
- 回訪週期中位數 60 天；鞋 68 天、包 119 天、床組 49 天。
- 目前名單（多次逾期規則）共 76 人。名單只存在 `data\crm\`（git-ignored），沒有傳送任何訊息。
- 隱私檢查：報告裡沒有任何姓名（檢查 2,156 個 ≥3 字的姓名）或電話（檢查 2,187 個）。與客號相同的 9 個 token 都是年份或彙總數字。
- 驗證：
  - 單元測試 54 個全綠。
  - 突變測試 13 個，其中 12 個轉紅。唯一沒變紅的是 reports/ 那條檢查，因為已被「repo 內只能在 data/」那條涵蓋（等效突變）。
