# 海報規格正本 — 字高由可讀距離推導,不由眼睛挑

> 前三版被退,共同死因是**我用眼睛決定字級**。這份把它換成公式。
> 每一條都附可查證來源;查不到本地實測的,明寫「找不到」,不編數字。

---

## 一、字高公式(唯一硬規則)

業界通用:**每 10 英尺閱讀距離需要 1 英寸大寫字高**。
來源:[Signs.com](https://www.signs.com/blog/signage-101-letter-height-visibility/)、
[Pannier Graphics](https://www.panniergraphics.com/blog/letter-height-visibility-chart-for-outdoor-sign-readability)

換算公制:**字高(mm) = 閱讀距離(m) × 8.33**

門口 A4 海報的距離分配與推導結果:

| 元素 | 該在幾公尺外讀到 | 字高 |
|---|---|---|
| 主標 | 3.0m(走過的人) | **25mm** |
| 優惠(現在來的理由) | 2.0m | **16.7mm** |
| 副標 | 1.8m(停下腳步) | **15mm** |
| 電話 | 1.5m | **12.5mm** |
| 地址 | 1.2m | **10mm** |
| QR 說明・營業時間 | 0.8m(站到面前) | **6.7mm** |

**副標必須是主標的 0.55–0.7 倍**(台灣門市規格卡)。25 × 0.6 = 15mm ✓

> **距離目標修訂(v6)**:優惠原本設 2.5m,實作後版面放不下。
> 重新想過:A4 門口海報上,**3 公尺負責讓人轉頭(那是主標的工作)**,
> 真正在讀優惠的人已經走到 2 公尺內。改為 2.0m 是依據行為修的,不是為了遷就版面——
> 若只是遷就版面,該砍的是照片高度而不是字高。

### 前三版為什麼失敗(用同一把尺量)

| 版本 | 副標 | 優惠 | 判定 |
|---|---|---|---|
| v3 | 7.5mm(0.9m) | 10mm(1.2m) | 兩個都要走到門口才讀得到 |
| v4 | 7.5mm(0.29 倍) | 10mm | 同上,而且副標比例只有規格的一半 |
| **v5** | **16.7mm(2.0m)** | **20.8mm(2.5m)** | 通過 |

## 一之二、視覺方向(v6 改版)

前五版都是「深綠滿版 + 置中白字」,老闆的原話是「我都不敢 PO 文」。三個具體原因:

1. **底色**:34.7% 面積的深綠實色,在噴墨會起皺、影印會出橫帶(印刷稽核已指出),
   而且視覺上像大賣場特價而不是精品護理。**v6 改成米白紙感底,綠色只做重點。**
   這同時是設計決定與印刷決定。
2. **編排**:全置中 = 靜態、廉價。**v6 改左對齊**,主標下方一道金色細線收住,
   建立一條清楚的左緣基準線。
3. **細節**:平色沒有質感。v6 加了紙張微噪點、照片下緣投影、
   標籤改成金色細線 + 疏字距小字(不用色塊)、優惠做成**票券式四角切角**。

字距(letter-spacing)在 PIL 沒有內建,v6 逐字繪製來控制——
主標收緊 −0.4mm,小字放鬆 +0.2~1.2mm。這是把「像排版過」和「像打字出來的」分開的地方。

## 一之三、主視覺產法(v7 起)

前後對比圖改用 **Grok 的 `image_edit`**:先生成一張「洗前」,再**從那張編輯出「洗後」**,
只清指定的髒污,不重新生成。這保證兩半是**同一雙鞋、同角度、同光、同背景**——
獨立生成兩張做不到這件事,那正是舊版對比圖的弱點。

實作要點(踩過才知道):

- **不要寫會被讀成「破損」的字。** 第一次寫「纖維被刷起毛」,模型畫出真的撕裂布條,
  鞋子看起來是壞的不是髒的。改寫成「表面平整完好,只是灰塵長期附著」才對。
- **背景不要放有標籤的瓶罐。** 模型為了避開可讀文字會把標籤擦成白色補丁,像被打碼。
  海報主視覺用單純淺色牆面 + 大留白。
- **「洗後」要明確列出「只准改哪幾處」與「必須完全不變的清單」**,
  否則它會順手改動你沒要求的區域(第一次把整片鞋面加了灰污,結果洗後比洗前髒)。
- **保留自然摺痕**:要求「變乾淨,不是變新」,皮面摺痕留著才有真實感。

**解析度**:`image_gen` 原生 1152×864,不可調。用作 216×84mm 的主圖時放大 1.15 倍,
**有效 261 DPI** —— 海報 1 公尺外看足夠(門檻 200)。
⚠ 若之後要做 A1 以上或近距離觀看的印刷品,這個來源不夠,要另尋高解析素材。

## 一之四、知識型版本(v8):海報要值得被拍下來

老闆:「內容太簡單、太單一」。對的——v7 只說了一句話,看完就走。
研究裡的判準是:**會被拍照存起來的內容才有價值**,而讓人停下來最有效的方式是**教一件他自己判斷得出來的事**。

v8 的主體是一張三欄表,教客人分辨白鞋三種黃:

| 看哪裡 | 為什麼黃 | 救不救得回 |
|---|---|---|
| 🟢 布面一整圈泛黃 | 洗劑殘留 | 洗得回來 |
| 🟡 鞋帶孔周圍發深 | 汗漬滲入 | 多半能淡化 |
| ⚪ 鞋邊膠條轉黃 | 橡膠氧化 | 刷不掉,只能淡化 |

三件事同時成立:**它有用**(客人真的能自己看)、**它誠實**(明講有一種救不回,反而建立信任)、
**它在賣**(三種裡兩種需要專業判斷,而 CTA 就是「拍一張,我告訴你是哪一種」)。

排版上的取捨:主圖從 84mm 縮到 43mm,**裁成只看中底那一帶**——
因為知識講的就是那裡,而知識表才是這張海報的主角。
主圖高度**由內容量反推**,不再事先猜一個數字。

### 又補一條渲染鐵則:文字也會超出容器的「寬度」

v8 第一版的價格行超出綠色卡片右緣。先前只檢查垂直堆疊(F7),水平方向沒人管。
`track()` 現在接受 `maxw`,超寬直接 assert 並指出超出幾 mm 與是哪一句。
它立刻抓到註腳超寬 2.2mm——那是眼睛看不出來、印出來才發現的量。

腳本:`scripts/build-poster-knowledge.py`(可重跑,改字會自己驗)

## 一之五、系列化(v9):同一版型,三個主題

一張海報教一件事,店裡貼兩週就看膩了。v9 把 v8 從「白鞋專用腳本」改成**吃主題設定的產生器**,
`TOPICS` 一個 key 一張:白鞋泛黃、精品包邊角、換季收棉被。

主圖改吃 `pair: (before, after)`,在腳本裡拼成對比圖。**新主題一律用 pair**,
因為 AFTER 必須是 BEFORE 編輯出來的(§一之三),獨立生成的兩張沒辦法保證是同一個物件。
`band: (top, height)` 是裁切帶,**height 要抓 ≈ 寬/5**,否則填滿海報寬度時會被垂直拉伸。

### 換主題最常撞到的一件事:字數

版型不變,但**每個欄位的可用寬度是固定的**,換主題就會超。實際命中三次:

| 欄位 | 上限(實測) | 撞到的內容 |
|---|---|---|
| 主標 | ~10 字 | 「精品包壞掉,從邊角開始」超 15.2mm |
| 註腳 | ~26 字 | 「邊角一旦磨穿…就是警訊。」超 12.9mm |
| CTA | ~14 字 | 需壓在綠卡內距內 |

這些**全部是 `maxw` 斷言擋下來的,沒有一個是眼睛看出來的**——這就是 F9 那條規則在還債。

### 主題設計的兩個規矩

1. **三列裡至少一列是「救不回」。** 明講救不回反而建立信任,而剩下兩列需要專業判斷,
   CTA 就是去接那兩列。誠實本身就是銷售機制,不是附註。
2. **CTA 要接得住可拍到的東西。** 棉被那張鉤子是「聞一下」,但氣味拍不出來,
   所以 CTA 落在看得見的結塊與黑點:「拍一張,我告訴你要不要洗」。
   鉤子可以用感官,**行動不行**。

## 二、版面

- **A4 直式 216×303mm(含 3mm 出血)**,安全邊 ≥10mm
- 留白目標約 30%
- 顏色:主色 60% / 輔色 30% / **強調色 10%,且只用在 CTA 或一個數字**
- 字體:**全橫排、粗黑體**(明體遠距易糊);中文行距 1.3–1.5 倍
- 資訊層級 **3 層**,元素順序:**鉤子 → 對象 → 利益 → 圖 → CTA → 店名/電話/LINE**
- **一張海報只推一個行動。** 完整價目放櫃檯,不放門口

## 三、QR

- 門口海報 **邊長 ≥25–30mm**,周圍留白 ≥5mm;櫃檯立牌 ≥40mm
- **不要只印 LINE ID 文字**——手打 ID 的放棄率遠高於掃碼
- 最佳組合:大 QR + 一句利益句 + 小字 ID 備援
- 來源:[LINE for Business 台灣](https://tw.linebiz.com/faq/Marketing/69/)

## 四、實作規則(寫進渲染器,不靠記憶)

`output/print/` 的渲染腳本必須:

1. 字高由 `距離 × 8.33` 產生,**不得手寫字級**
2. 斷言副標/主標比例在 0.5–0.75
3. `put()` 回傳文字實際底部(中文約字級 ×1.28),後續元素必須在它之下
4. 存檔前斷言底部 ≤ 頁高 − 10mm

第 3 條是 v4 與 v5 各犯一次的坑:只算「區塊高度」不算「文字實際佔高」,
文字就會壓到下一個元素身上,而且**不會報錯**。
