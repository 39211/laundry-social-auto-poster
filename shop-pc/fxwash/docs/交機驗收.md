# 門市交機驗收清單

這份清單用來區分「安裝完成」和「可以交給店家使用」。每一格都要記錄實際日期、測試手機／帳號、結果與證據位置；程式測試全綠不代表這些格子自動通過。

## G1：LINE 官方平台

- [ ] 後台登入帳號、Messaging API、Webhook URL 由店主提供並以平台回讀確認。
- [ ] `connections.py verify-line` 回讀 Bot 名稱／Basic ID 與目前 webhook endpoint。
- [ ] `connections.py test-webhook` 回傳成功，門市端紀錄到 LINE 的空 events 測試 POST。
- [ ] 若由商品包套用 webhook，執行紀錄要包含 `apply-webhook --confirm` 的平台回讀結果。
- [ ] 圖文選單與每一格動作在手機逐格點選，重開聊天室後仍正確。
- [ ] 不改動既有品牌選單，除非店主另行授權改版。

## G2：客人完整旅程

- [ ] 純文字問價、照片問價、預約外收送、營業時間、店址、真人接手。
- [ ] 傳照片後能收到照片已收妥、需求補充與店員接手提示。
- [ ] 不把模型猜測當成確定報價；估價必有現場確認但書。

## G3：可信資料與付款

- [ ] 完整手機號碼查件，查件權限與同意流程已測。
- [ ] 連接器讀到「處理中／已完成／已取件」的資料變更，記錄實際延遲。
- [ ] 連接器中斷時回人工接手，不回傳假查件結果。
- [ ] 若使用 merchant QR，確認付款後由店員人工核銷；若要自動回呼，另案完成 LINE Pay Online API、簽章、金額核對與案件狀態更新。
- [ ] LINE Pay Online 模式先用 sandbox reserve/confirm 測試；正式環境另核對商店 ID、Channel ID、Channel Secret、伺服器 IP 白名單與退款流程。

## G4：店員接手與復原

- [ ] 店員群收到照片、預約、查件與人工接手通知，且沒有重複通知。
- [ ] 店員標記「已接手」後 AI 不搶回對話；解除後才恢復。
- [ ] 重啟後狀態、備份還原、日誌與人工流程可接續。

## G5：複製到下一家店

- [ ] 空白 Windows 電腦可用 `Install.ps1` 建立新實例，沒有帶入上一家客資或金鑰。
- [ ] 第二家店只需填 `shop.json`、放入自己的連接器設定與秘密，即可完成 validate/health。
- [ ] 另一家店的真 LINE、手機、店員群、查件、付款與斷線驗收全部留證。

## 交機判定

只有 G1 到 G5 都有真實證據才可標記 `ready_for_owner_handover`。若只有安裝成功、設定檔正確、測試全綠或 HTTP 200，狀態仍是「試點候選」，不能對外宣稱已完成商品交付。
