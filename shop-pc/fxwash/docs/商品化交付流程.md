# 洗衣 LINE 商品化交付流程

這是每家新門市的固定交付順序。流程把「客戶選了」和「客戶真的能用」分開記錄。

## 1. 收件與選配

向店主收集：店名、地址、電話、地圖、營業時間、收送規則、價目表、常見問答、品牌素材、店員群、查件系統種類、LINE 官方帳號狀態、LINE Pay 入口、照片辨識是否同意，以及要選的方案與風格。

不收進商品包：Channel secret、access token、LINE Pay secret、客戶名單、正式資料庫、未遮罩的客人照片。這些只在門市現場以秘密檔或受控連線設定。

## 2. 產生門市實例

在乾淨資料夾執行 `Install.ps1`，產生獨立的 `shop.json`、`config`、`data`、`logs`、`backups` 和 `secrets`。安裝器拒絕覆蓋非空資料夾，並留下 `INSTALL-REPORT.json`。

接著用 `patch_shop_json.py` 寫入方案、風格、付款模式與公開網址，執行：

```powershell
python -B laundry.py validate --shop .\shop.json
python -B laundry.py catalog
python -B laundry.py selection --shop .\shop.json
```

## 3. 設定門市連接

先做本機欄位檢查，再在店家現場填入 LINE 憑證、LINE Pay 入口和查件資料源。每一家店都要有自己的備份，不能把私享家資料直接複製過去。

查件連接器先以唯讀為原則。資料源不明、查件授權未完成或資料延遲未量測時，客服要轉店員，不能回傳猜測的件況或餘額。

## 4. 平台與手機驗收

依序記錄五種狀態：

1. **草稿**：文案、圖片、按鈕動作與模組已整理。
2. **程式完成**：本機測試通過，資料隔離與秘密檔閘門通過。
3. **平台回讀**：LINE 後台讀回帳號、Webhook、選單與動作設定。
4. **手機逐格實測**：真手機按六格、傳照片、查件、外收送、付款，確認每一步的回覆與店員通知。
5. **交機**：店員能接手、知道故障時怎麼停用與回復，店主簽收測試結果。

HTTP 200、測試全綠或設定已保存，只能證明其中一小段，不得直接寫成已交付。

## 5. 交付內容

交給店主：

- 選定的方案、模組、風格與未啟用項目。
- `shop.json` 的非秘密範本與門市資料清單。
- LINE 後台回讀紀錄、手機逐格測試表與店員接手說明。
- 備份／還原方式、斷線時的人工處理方式、版本與變更紀錄。
- 尚未完成的整合項目，例如 LINE Pay Online API、集點後台、第二家店 POS 連接。

完成這些證據後，才可以把該門市標成「可交機」。商品包本身不會把未驗收功能包裝成已上線能力。
