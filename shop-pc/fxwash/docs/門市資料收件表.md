# 新門市收件表

先收齊這些資料，才開始建立門市實例。金鑰、客戶名單和 POS 匯出檔不要用聊天訊息傳送，改在店家自己的電腦現場放入指定資料夾。

## 店家資料

- 門市名稱、地址、電話、Google 地圖網址、品牌標語。
- 每週營業時間、店休、外收送範圍、費用、可預約時段與取消規則。
- 現有價目表、特殊材質／特殊處理的人工報價規則、預估處理天數。
- 要不要開啟照片詢問、照片保存天數、外部影像 AI 的告知與同意版本。

## LINE 官方帳號

- 已有帳號：官方帳號管理員登入，由店主在店家電腦操作；不要把密碼交給交付包。
- Messaging API channel access token、channel secret：只放新門市實例的 `secrets/line-channel.json`。
- Webhook 可用 HTTPS 網址與後台回讀結果。
- 店員通知群組由店員現場加入並完成綁定，不在交付包預先寫入群組 ID。
- 品牌 Logo、選單圖片、六格動作；既有品牌選單要先凍結，不得默認改版。

## 洗衣系統／查件

- 系統名稱與版本、安裝根目錄、允許的唯讀查詢方式。
- 查詢鍵：完整手機、客戶編號、洗件編號中哪些可以使用。
- 狀態對照：收件、處理中、完成、已取件各自對應哪個欄位。
- 一筆真實測試資料與店員可核對的結果；不得把整份客戶資料帶進商品包。

## 付款

- 目前是 `disabled`、客人自行輸入金額的 `merchant_qr`，或另案的 LINE Pay Online API。
- 若要自動核銷，還要有商家 API／sandbox 資格、固定案件金額、交易編號對應、回呼網址、驗簽和退款規則。

## 交機聯絡人

- 店主、店員群管理者、可以操作 POS 的人、可以拿測試手機的人。
- 可安排至少一段時間做手機逐格、照片、位置、查件、付款、店員接手、重啟與備份還原測試。
